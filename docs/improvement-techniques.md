# Приёмы улучшения document-QA систем

Справочник к защите: что существует, что чинит, что применимо здесь. Колонка «Нам» — решение по этому проекту с обоснованием.

## Подготовка данных

| Приём | Что чинит | Нам |
|---|---|---|
| Contextual Retrieval | к каждому чанку LLM дописывает контекст «это раздел X, речь про Y», снимая потерю смысла при нарезке | если бы строили RAG всерьёз. С промпт-кэшем недорого |
| Late chunking | эмбеддинг считается по всему документу и режется после, контекст сохраняется | альтернатива предыдущему, та же цель |
| RAPTOR | рекурсивная кластеризация и суммаризация в дерево, поиск на разных уровнях абстракции | **уже есть даром**: иерархия разделов проставлена автором отчёта, 178 закладок. Строить дерево не нужно |
| Propositional chunking | разбиение на атомарные утверждения вместо кусков текста | избыточно для одного документа |
| Извлечение в структуру | таблицы в записи с провенансом, числа отделены от текста | **ядро решения** |
| Knowledge graph из документа | сущности и связи вместо плоского текста | не окупается на одном отчёте |

Формулировка для защиты: маршрутизация по закладкам это RAPTOR, которому не нужно строить дерево, потому что дерево лежит в документе.

## Поиск

| Приём | Что чинит | Нам |
|---|---|---|
| Гибрид BM25 + dense | эмбеддинги плохо находят числа и точные термины, лексический поиск хорошо | **обязательно в векторную ветку**: без него сравнение нечестное |
| Reranker (cross-encoder) | берём top-50 и переупорядочиваем в top-8, точность выборки растёт | только если векторный режим пойдёт из замера в продукт |
| Декомпозиция вопроса | сложный вопрос режется на подвопросы, каждый ищется отдельно | **да, под вопрос про опережающий рост прибыли**: он multi-hop по своей природе |
| HyDE | поиск не по вопросу, а по сгенерированному гипотетическому ответу | не нужен: у нас навигация по структуре, а не по смысловой близости |
| Step-back prompting | сначала общий вопрос, потом конкретный | частично покрыт роутером |
| Self-query | из вопроса извлекаются фильтры (год, сегмент) и применяются к метаданным | **дёшево и в тему**: поля `p` и `s` есть в каждой записи |

## Генерация

| Приём | Что чинит | Нам |
|---|---|---|
| Structured output | ответ приходит объектом с полями и ссылками, а не свободным текстом | **да**: атрибуция перестаёт зависеть от послушности модели |
| Citation-aware generation | каждое утверждение привязано к идентификатору фрагмента | покрыто провенансом в записях |
| Chain-of-verification | модель формулирует проверочные вопросы к собственному ответу и отвечает на них | дорого, но оправдано на причинно-следственном вопросе |
| Self-consistency | несколько сэмплов и голосование по числу | дорого; сверка с предвычисленным агрегатом даёт то же дешевле |
| Критик-проход | вторая модель ищет ошибки в ответе первой | в продукте да, в двухчасовом прототипе нет |

## Надёжность

Здесь лежит самое выгодное по соотношению эффекта к трудозатратам.

| Приём | Что чинит | Нам |
|---|---|---|
| **Проверка чисел регуляркой** | из ответа вытаскиваются все числа, каждое ищется в поданном контексте; не нашлось — флаг | **делаем обязательно**. Десять строк кода, ловит галлюцинацию в цифре напрямую, без второй модели |
| Контрольные суммы разбора | сумма сегментов против консолидированного итога | **делаем**: детектор собственной ошибки парсинга |
| Groundedness-проверка (RAGAS, TruLens) | отдельный проход «выводится ли утверждение из источника» | тяжело для двух часов, но правильное направление для продукта |
| Калиброванный отказ | система отказывается отвечать при низкой уверенности | частично: роутер возвращает confidence |
| LLM-as-judge | автоматическая оценка ответов на большом наборе | десять эталонов вручную дешевле и надёжнее |
| Перекрёстная сверка двух путей | предвычисленный агрегат против SQL-ответа модели | заложено в P2-модуль |

## Эксплуатация

| Приём | Что чинит | Нам |
|---|---|---|
| Промпт-кэширование | повторные вопросы к тому же документу дешевеют примерно в десять раз | учтено в расчёте экономики |
| Семантический кэш ответов | повторяющиеся вопросы не доходят до модели | для демо не нужен |
| Каскад моделей | дешёвая отвечает, дорогая берёт сложные вопросы и проверяет | естественное продолжение матрицы «режим × модель» |
| Батчинг | половинная цена на офлайн-прогонах | применимо к прогону замера, не к живым вопросам |

## Что берём в прототип

Четыре приёма влезают в отведённое время и дают наибольший эффект:

1. **Проверка чисел регуляркой** — вне конкуренции по цене и эффекту.
2. **Гибрид BM25 + dense в векторной ветке** — условие честности замера.
3. **Декомпозиция вопроса** — под причинно-следственный вопрос.
4. **Structured output** — цитаты как поле объекта, а не как обещание в промпте.

Остальное идёт в раздел «не сделано» с условием включения.
