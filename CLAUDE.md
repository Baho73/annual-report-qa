# GRACE Framework — Project Engineering Protocol

## Keywords
annual report QA, IFRS, PDF parsing, table extraction, long context, section routing, RAG comparison, LLM, guardrails, provenance, Streamlit

## Annotation
Прототип AI-ассистента, отвечающего на вопросы по годовому отчету публичной компании (МКПАО «Яндекс», 2025). Тестовое задание на позицию AI Developer, ограничение 1-2 часа, защита решения голосом. Ядро: разбор PDF на разделы по встроенным закладкам, разворот числовых таблиц в длинный JSON с провенансом, маршрутизация вопроса по разделам вместо векторного поиска, замер трех стратегий поиска на общем наборе вопросов, отказ от инвестиционных рекомендаций как проектное решение.

## Core Principles

### 1. Never Write Code Without a Contract
Перед генерацией модуля создать или обновить его MODULE_CONTRACT с PURPOSE, SCOPE, INPUTS, OUTPUTS. Контракт первичен, код реализует контракт.

### 2. Semantic Markup Is Not Comments
`# START_BLOCK_<NAME>` и `# END_BLOCK_<NAME>` — навигационные якоря: уникальные имена, парность, ~500 токенов между ними.

### 3. Knowledge Graph Is Always Current
`docs/knowledge-graph.xml` — единственная карта проекта. Новый модуль идет в граф, новая зависимость идет в CrossLink.

### 4. Top-Down Synthesis
RequirementsAnalysis → Technology → DevelopmentPlan → Code.

### 5. Governed Autonomy (PCAM)
Свобода в том, КАК реализовать. Контракт и граф определяют, ЧТО.

## Специфика этого проекта

### Ответ без источника не является ответом
Каждое число в ответе несет номер страницы. Провенанс встроен в структуру данных (поле `pg` в каждой записи), а не выпрашивается у модели промптом. Модель, которая физически не может процитировать число без страницы, надежнее модели, которую попросили это делать.

### Система обязана уметь сказать «в документе этого нет»
Главный риск продукта для финансов — не отсутствие ответа, а уверенный ответ из памяти модели. Проверяется отдельным тестом на отчетности МСФО, где бизнес-риски не раскрыты: правильное поведение — перечислить раскрытое и назвать границу документа.

### Арифметика в коде, формулировка в модели
Приросты, доли и вклад в прирост считает pandas. LLM получает готовые числа и формулирует вывод. Модель не умножает и не делит.

### Инвестиционные рекомендации не выдаются
Ответ разрезан на фактическую часть (драйверы, риски, динамика — выдается полностью) и оценочную (вердикт «покупать» — не выдается никогда). Это проектное решение, а не недоделка, и оно проговаривается на защите.

### Удешевление только через повышение качества
Цена ошибки здесь несоизмерима с ценой токенов: перепроверка ответа аналитиком стоит в 2-5 раз дороже самого ответа, а одна пойманная ошибка убивает режим «доверяю и не проверяю» и обесценивает сотню верных ответов. Поэтому снижение класса модели (обмен качества на деньги) допустимо только до порога, подтверждённого замером, а сокращение контекста (устранение шума) применяется без ограничений: оно даёт экономию и точность одним движением. Сначала режем контекст, потом опускаем модель.

### Замер вместо мнения
Три стратегии поиска (полный контекст, роутер по разделам, векторный) прогоняются на одних десяти вопросах. Векторная ветка делается добросовестно: чанки по разделам, таблица не рвется, top-8, многоязычные эмбеддинги. Соломенное чучело обесценивает замер.

## File Structure
```
docs/
  knowledge-graph.xml    — карта проекта
  requirements.xml       — use cases
  technology.xml         — стек и версии
  development-plan.xml   — модули и контракты
  architecture.md        — архитектурное обоснование (для защиты)
  contradictions.md      — разбор противоречий ТЗ и архитектуры по ТРИЗ
report_qa/
  config.py              — пути, ключи, модели
  llm.py                 — слой OpenRouter
  parse.py               — PDF → разделы по закладкам, таблицы → JSON, агрегаты
  router.py              — выбор разделов под вопрос
  context.py             — сборка контекста (XML-секции + JSON-таблицы)
  vector.py              — векторный режим для замера
  answer.py              — промпт, вызов модели, атрибуция, guardrail
eval/
  questions.yaml         — 10 вопросов с эталонами
  run_eval.py            — прогон трех режимов, метрики
app.py                   — Streamlit демо
data/
  yandex_annual_report_2025.pdf   — рабочий документ (201 стр)
  yandex_ifrs_fy2025.pdf          — контрольный пример для теста на честность
  sections.json / tables.json     — результат разбора (артефакты сборки)
build/                   — одноразовые скрипты разбора
```

## Rules for Modifications
1. Читать MODULE_CONTRACT перед правкой файла.
2. Изменились сигнатуры — обновить MODULE_MAP.
3. Добавлен или удален модуль — обновить knowledge-graph.xml.
4. Исправлен баг — добавить запись в CHANGE_SUMMARY.
5. Не удалять якоря семантической разметки.
6. Кодировка: все файловые операции с `encoding="utf-8"`, запуск python с `PYTHONUTF8=1`. Документ русский, cp1251 по умолчанию ломает вывод.
7. Числа из PDF проходят нормализацию до попадания в JSON. Скобки означают минус, пробел — разделитель тысяч, запятая — десятичный разделитель, единица измерения выносится в отдельное поле.
